# Continuity and current experience

Use this reference when a long task is interrupted by new messages or when old experience competes with a newer correction.

## Preserve the active outcome

Classify a new message by its relationship to the active outcome:

- **Question or status request:** answer it, then resume the unfinished authorized work.
- **Correction or critique:** replace the affected premise, step, or output and continue from the nearest valid checkpoint.
- **Additional requirement:** merge it when compatible; expose a real conflict when it changes scope or acceptance.
- **Local pause:** stop only the named branch, input, or method. Continue independent in-scope work.
- **Whole-task pause, cancellation, or replacement:** stop or switch as explicitly requested.

Do not infer cancellation from recency alone. Do not ignore an explicit correction merely to preserve momentum.

Before ending or resuming after compaction, recover:

1. the active outcome;
2. the latest effective correction;
3. accepted results that must be preserved;
4. unfinished work;
5. the exact blocker, if any;
6. the next safe falsifiable checkpoint.

A completed command, phase, draft, or status explanation is not the requested outcome unless the acceptance contract says it is.

## Retrieve current applicable experience

Use the project's existing decisions, lessons, component registry, receipts, and evidence pointers. Search by current goal, object, version, failure class, and invalidation signal. Prefer:

1. current explicit instruction and direct evidence;
2. accepted current workflow and latest correction;
3. validated local lessons with matching scope;
4. counterexamples and failed routes that can still change the next action;
5. older narrative only when needed to resolve a contradiction.

Do not load every historical mistake by default. Do not hide a still-relevant counterexample merely because it is old. Keep retrieval output non-authoritative until reconciled with current sources.

## Run the learning cycle

Use one auditable cycle:

```text
explore a possibility
-> test the highest-impact uncertainty
-> admit only decision-relevant evidence
-> retrieve it when a matching goal or failure appears
-> reuse within its scope
-> revise or retire it when negative feedback invalidates the relation
```

Small frozen cases can test whether a rule produces the intended structured judgment. They do not prove natural-task behavior, cross-model improvement, or reduced rework. Require comparable real-task evidence before making those claims.


## Deliver messages at the right time

Send corrections, authority changes, and execution-blocking instructions promptly. Queue non-urgent summaries when immediate delivery would interrupt a monitored or long-running action. Delivery timing changes communication, not authority: the receiver must still reconcile the message with its current objective and evidence.
